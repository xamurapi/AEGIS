## M11.1. Назначение и честный разбор разрыва

Из пяти строк наброска **три уже сданы**. Писать ТЗ так, будто не сдано ничего,
означало бы переделать M6 второй раз, поэтому граница проводится построчно.

| Строка `развитие.txt` | Состояние | Где |
|---|---|---|
| «Какая стратегия дала лучший результат?» | **Сдано.** Библиотека держит статистику по классам задач, выбор — детерминированный UCB. | `layers/reasoning/library.py`, `ReasoningEngine._ucb` |
| «Почему?» | **Не сделано.** | — |
| «Можно ли придумать принципиально другой способ?» | **Сделано наполовину.** Синтез применяет каталог трансформаций к действующей стратегии. Это поиск в окрестности, а не другой способ. | `layers/reasoning/synthesis.py` |
| «Проверить» | **Сдано.** Арена: held-out, регрессионный гейт, порог стоимости, `trial → active → retired`. | `layers/reasoning/arena.py` |
| «Если лучше — заменить» | **Сдано.** | `arena.evaluate`, `library.promote` |

Итого модуль обязан закрыть ровно два разрыва.

**Разрыв 1: «Почему?».** Система знает, *что* стратегия победила в классе задач.
Она не знает, *какая её часть* дала выигрыш. Следствие не косметическое: синтез
слеп. Он перебирает фиксированный каталог трансформаций в фиксированном порядке
и не может предпочесть трансформацию потому, что именно она дала прошлый
выигрыш. Опыт «что сработало» накапливается на уровне стратегий и не
накапливается на уровне *причин*.

**Разрыв 2: «принципиально другой способ».** Каждый кандидат — это действующая
стратегия ± одна правка. Расстояния в пространстве стратегий не существует,
давления в сторону структурно иных решений нет. Это разница между вариацией и
изобретением.

Петля M11 — метауровень над M6: её входные данные — результаты контура
рассуждений, её выход — изменение того, **как порождаются стратегии**. M6 меняет
стратегии; M11 меняет генератор стратегий.

## M11.2. Границы (что модуль не делает)

Фиксируется, чтобы объём был честным.

1. **Не добавляет ни одной операции DSL.** Интерпретатор остаётся на своих 12
   операциях. Стратегия остаётся списком записей, а не Python. Синтезированная
   стратегия, будь она кодом, была бы исполнением произвольного кода с приятным
   названием; это решение M6 не пересматривается. Тест утверждает `len(OPS) == 12`.
2. **Не переписывает арену.** Гейты приёмки M6.8 применяются без изменений.
   Новизна покупает право быть оценённым, никогда — право быть принятым.
3. **Не заменяет M5.** Эволюция генома и метакогниция независимы: M5 ищет по
   числам конфигурации, M11 — по структурам стратегий.
4. **Не изобретает вне объявленного каталога скелетов.** Система детерминированно
   перебирает скелеты из закрытого списка (M11.6) и заполняет их по таблице
   механизмов. Добавление нового скелета — действие человека. Это честная граница,
   а не заглушка: снять её означало бы порождать структуру программы свободно,
   что возвращает нас к пункту 1. Что потребуется для снятия — в M11.20.
5. **Механизм-объяснение никогда не управляет исполнением.** Свободный текст от
   кортекса хранится для человека и не читается кодом (M11.5).

## M11.4. Структуры данных

```python
@dataclass(frozen=True)
class Edit:
    """Одна атомарная правка, отличающая кандидата от действующей стратегии."""
    kind: str          # "insert" | "remove" | "param" | "wrap" | "reorder"
    position: int      # индекс шага в канонической форме
    op: str            # операция, к которой относится правка
    key: str = ""      # для kind == "param"
    before: object = None
    after: object = None
```

```python
@dataclass(frozen=True)
class EditAttribution:
    edit: Edit
    effect: float          # pass(S) − pass(S без правки), доли
    n: int                 # объём held-out выборки
    wilson_low: float      # нижняя граница 95% интервала эффекта
    p_value: float
    confirmed: bool        # прошла BH при q = META_FDR_Q и effect ≥ META_MIN_EFFECT
```

```python
@dataclass(frozen=True)
class Explanation:
    strategy: str              # имя принятой стратегии
    incumbent: str             # с чем сравнивалась
    weakness: str              # идентификатор слабости (M6.6)
    gain: float                # Δpass_held_out, ради которого стратегия принята
    edits: tuple[EditAttribution, ...]
    mechanism: str             # из закрытого словаря; "" если ни одна правка не подтверждена
    narrative: str = ""        # свободный текст кортекса; не читается кодом
    status: str = "supported"  # supported | unsupported | contested
    created_tick: int = 0
```

```python
@dataclass
class MechanismCredit:
    """Сколько раз механизм приводил к принятой стратегии — по признакам слабости."""
    mechanism: str
    feature: str               # признак слабости, например "steps>=4" или "incomplete"
    attempts: int = 0
    accepted: int = 0
    total_effect: float = 0.0  # сумма подтверждённых эффектов
```

Инварианты, проверяемые тестами:

- `Explanation.mechanism` непусто **тогда и только тогда**, когда хотя бы одна
  `EditAttribution.confirmed` истинна;
- `status == "unsupported"` ⇒ объяснение не участвует в упорядочивании синтеза;
- `narrative` не встречается ни в одном условии кода (тест грепает модуль).

## M11.5. Атрибуция: «Почему?»

### M11.5.1. Почему аблация, а не объяснение

Объяснение — самая простая вещь для подделки. Языковая модель произведёт
правдоподобную причину для любого исхода, включая случайный, и отличить её от
верной по тексту нельзя. Поэтому «почему» в этом модуле — **проверяемое
утверждение**, а не текст: убрать ту часть стратегии, которой объяснение
приписывает выигрыш, и выигрыш обязан исчезнуть. Объяснение, не выдержавшее ни
одной аблации, отклоняется.

### M11.5.2. Алгоритм

Дано: принятая стратегия `S`, действующая `I`, слабость `W`, выигрыш `Δ`.

1. `E = diff(I, S)` — список атомарных правок в канонической форме (M11.6.1).
   Если `|E| > META_MAX_EDITS` (по умолчанию 4), стратегия помечается
   `unsupported`: атрибуция при слишком многих одновременных правках потребовала
   бы перебора подмножеств и не была бы измерением. Это ограничение на
   объяснимость, а не на приём стратегии — арена уже её приняла.
2. Для каждой правки `e ∈ E` строится `S∖e` — `S` с откатанной правкой — и
   измеряется доля решённых на **held-out** части слабого класса объёмом
   `META_ABLATION_N` (по умолчанию 60). Held-out обязателен: доля, измеренная на
   том же наборе, по которому кандидат отбирался, приписала бы выигрыш подгонке.
3. `effect(e) = pass(S) − pass(S∖e)`; интервал — по Вильсону на разности долей;
   `p_value` — по двустороннему тесту пропорций (реализация из `util/stats.py`,
   без внешних библиотек).
4. **BH-коррекция по всей семье `|E|` сравнений**, а не по тем, что выглядели
   удачно. Правка подтверждена при `q ≤ META_FDR_Q` (0.10) **и**
   `effect ≥ META_MIN_EFFECT` (0.03) **и** `wilson_low > 0`. Три условия, а не
   одно: значимость без величины даёт объяснения ни о чём, величина без
   значимости — объяснения из шума.
5. Механизм присваивается по правке с максимальным подтверждённым эффектом,
   через объявленное отображение `op × kind → mechanism` (M11.5.3). Если
   подтверждённых правок нет, `mechanism = ""`, `status = "unsupported"`.
6. Кортекс (роль `DEEP`, если доступна) получает слабость, `S`, `I` и **уже
   посчитанные** атрибуции и возвращает `narrative` плюс *предполагаемый*
   механизм строго по схеме. Если предложенный механизм не совпадает с
   вычисленным, объяснение получает `status = "contested"`, в телеметрию идёт
   `aegis.meta.contested`, а в упорядочивании синтеза используется **вычисленный**.
   Кортекс не может изменить ни один числовой вывод.

### M11.5.3. Закрытый словарь механизмов

Свободный текст нельзя посчитать и нельзя протестировать, поэтому механизм —
перечисление. Отображение объявляется декларативно в `mechanism.py`:

| Механизм | Порождается правкой |
|---|---|
| `decomposition_shortened_chain` | `insert`/`param` над `DECOMPOSE` |
| `verification_caught_error` | `insert` над `VERIFY` |
| `abstention_avoided_confident_error` | `insert` над `ABSTAIN` |
| `voting_reduced_variance` | `insert`/`param` над `VOTE` |
| `computation_replaced_guess` | `param`, заменивший `LLM_STEP` на `COMPUTE` |
| `prediction_pruned_branch` | `insert` над `PREDICT` или `BRANCH` |
| `retrieval_supplied_missing_fact` | `insert` над `RETRIEVE` |
| `reflection_reordered_work` | `reorder`, `wrap` |

Тест утверждает: каждая пара `(op, kind)`, которую может породить `diff`,
отображается ровно в один механизм, и обратное отображение не пусто ни для
одного механизма (иначе механизм декоративен).

### M11.5.4. Что аблация доказывает, а что нет

Формулируется прямо, потому что переоценка здесь была бы худшим исходом
документа. Аблация устанавливает **причинный вклад** правки в измеренный
выигрыш. Она не устанавливает «почему» в человеческом смысле — метка механизма
остаётся гипотезой о причине. Эта гипотеза проверяема только своими
предсказаниями: механизм зарабатывает кредит тогда, когда построенные на нём
стратегии проходят арену (M11.6.3). Тем самым «почему» верифицируется не текстом,
а тем, что оно позволяет предсказать следующий успех.

## M11.6. Изобретение: «принципиально другой способ»

### M11.6.1. Каноническая форма и расстояние

Расстояние без каноникализации мерило бы форматирование. Каноникализация:
рекурсивный обход DSL, сортировка независимых параметров по ключу, нормализация
числовых литералов, удаление шагов без наблюдаемого эффекта (`REFLECT` без
последующего чтения). Результат — детерминированное дерево и его `blake2b`-хеш.

```python
def distance(a: Strategy, b: Strategy) -> float:   # [0.0, 1.0]
```

Половина веса — нормализованное редакционное расстояние по каноническим деревьям,
половина — расстояние Жаккара по мультимножествам операций. Первое чувствительно
к структуре, второе — к составу; по отдельности каждое обманывается
(перестановка тех же операций даёт нулевое жаккардово расстояние, а замена
операции при той же форме — малое редакционное). Требования, закрепляемые
тестами: `distance(a, a) == 0`; симметричность; `distance > 0` для стратегий с
разными хешами; инвариантность к перестановке независимых параметров.

`StrategyArchive` — по образцу `NoveltyArchive` из M5, но над стратегиями:
помнит всё, что оценивалось, и отсекает почти-дубликаты **до** оценки. Оценка —
дорогой шаг (арена — секунды), а генератор в окрестности порождает
почти-дубликаты постоянно.

### M11.6.2. Каталог скелетов

Скелет — форма стратегии без параметров; закрытый объявленный список. Минимум
шесть, все структурно различны (попарное `distance ≥ META_FAR`):

| Скелет | Форма |
|---|---|
| `decompose_solve_verify` | `DECOMPOSE → LOOP(SOLVE) → VERIFY` |
| `predict_branch_abstain` | `PREDICT → BRANCH(SOLVE, ABSTAIN)` |
| `retrieve_compute_verify` | `RETRIEVE → COMPUTE → VERIFY` |
| `vote_of_alternatives` | `VOTE(n, body=[SOLVE, COMPUTE])` |
| `verify_first_then_solve` | `VERIFY → BRANCH(SOLVE, DECOMPOSE → SOLVE)` |
| `reflect_retry_bounded` | `SOLVE → REFLECT → BRANCH(ABSTAIN, LOOP(SOLVE))` |

Заполнение параметров детерминированно: по таблице кредита механизмов для
признаков данной слабости, при равенстве — по каноническому порядку. Ни одного
обращения к ГПСЧ (§3.1); там, где нужна квазислучайность, — Холтон и
хеш-индексация, как в M5 и M7.

### M11.6.3. Кредит механизмов управляет порядком

Здесь замыкается стрелка `опыт → изменение поведения` на метауровне, и здесь же
находится измеримое «поведение изменилось».

`order(weakness) -> tuple[str, ...]` возвращает порядок трансформаций и скелетов,
отсортированный по детерминированному UCB над таблицей кредита:

```
score(m, f) = accepted/attempts + META_MECHANISM_C · sqrt(ln N / attempts)
```

при `attempts == 0` — `+inf` (непробованный механизм пробуется; любое конечное
значение по умолчанию позволило бы одному удачному механизму навсегда вытеснить
непробованные). Синтез M6 берёт порядок отсюда вместо фиксированного.

**Это и есть изменение поведения**, а не отчёт: до M11 порядок кандидатов не
зависел от истории причин, после — зависит. Метрика: `META_ORDER_DELTA` —
доля слабостей, для которых порядок отличается от фиксированного; должна быть
`> 0`, иначе таблица декоративна.

### M11.6.4. Квота новизны, а не бонус

Из `K` кандидатов за цикл `⌈K × META_FAR_SHARE⌉` (по умолчанию 0.25) обязаны
происходить от дальнего генератора и иметь `distance ≥ META_FAR` (0.5) от всего
архива. Квота, а не добавка к скору: добавку можно перевесить, квоту — нет, и
она детерминирована. Остальные кандидаты — окрестность (существующий путь M6).

**Приёмка не смягчается.** Все гейты M6.8 действуют без изменений. Дальний
кандидат, не давший `Δpass_held_out ≥ REASON_MIN_GAIN`, отклоняется так же, как
близкий.

### M11.6.5. Память о неудачах

Скелет, `META_RETIRE_AFTER` раз (по умолчанию 3) провалившийся на данном наборе
признаков, отставляется для этого набора **навсегда** и записывается в реестр.
Причина та же, что у вечных опровержений M7: иначе каждый цикл заново
изобретает одну и ту же привлекательную структуру. Отставка — по паре
`(скелет, признаки)`, не по скелету: структура, бесполезная на неполных данных,
может быть верной на длинных цепочках.

## M11.7. Интеграция в ядро

### M11.7.1. Substrate

- `MetaCognition` конструируется **после** `reasoning` (нужен доступ к библиотеке,
  арене и детектору слабостей) и получает `telemetry`, как остальные контуры;
- `full_status()["metacognition"]` — сводка: число объяснений по статусам, топ
  механизмов, отставленные скелеты, `order_delta`;
- участвует в цикле персистентности и в `publish_metrics`;
- `state_snapshot()` включает объяснения и таблицу кредита: структура, не
  попавшая в снимок, — слепое пятно теста детерминизма (§M9.4).

### M11.7.2. Реестр действий (Приложение A)

Два новых действия, объявляются в `layers/actions.py`:

| Действие | Драйв | tok / ms / proc / net / train | Предусловия | Исполнитель | min_int | SC |
|---|---|---|---|---|---|---|
| `attribute_strategy` | coherence | 900 / 300 / 1 / 0 / 0 | есть принятая стратегия без объяснения | `MetaCognition.attribute` | 300 | |
| `invent_strategy` | competence | 2000 / 5000 / 0 / 0 / 0 | есть слабость ранга 1; квота новизны не выбрана | `MetaCognition.invent` | 300 | |

Оба — не `safety_critical`: политика поведения может их подавить, ресурсный пол
им не гарантирован, эволюция может свести их к нулю. Метакогниция полезна, но
система обязана работать без неё.

### M11.7.3. Тик и бюджеты (§3.4)

- **REFLECT**: только учёт — постановка стратегий в очередь на атрибуцию,
  обновление таблицы кредита, публикация метрик. Тиковая часть ≤ 3 мс, бюджет
  фазы (15 мс) не расширяется.
- **ACT**: `attribute_strategy` и `invent_strategy` исполняются под арендой, как
  обычные действия.
- **Аблация исполняется в пуле оценки, не в тике.** `META_MAX_EDITS × META_ABLATION_N`
  прогонов — это секунды; §3.4 требует, чтобы тяжёлая работа покидала тик.
  Отдельный тест падает, если аблация выполнилась синхронно внутри `tick()`.
- Результат аблации приходит на том тике, на котором он готов, — как результат
  бенчмарка. В тесте детерминизма он пинуется наравне с `evaluator.run`, по той
  же причине: детерминирован цикл, а не планировщик ОС.

### M11.7.4. Гены (M5, стадия 10)

| Ген | Тип | Диапазон | По умолчанию | Ридер |
|---|---|---|---|---|
| `meta_far_share` | float | 0.0–0.5 | 0.25 | `MetaCognition.invent` — квота |
| `meta_min_effect` | float | 0.01–0.10 | 0.03 | `attribution.confirm` |
| `meta_ablation_n` | int | 20–200 | 60 | `attribution.ablate` |
| `meta_mechanism_c` | float | 0.0–2.0 | 0.7 | `mechanism.order` |

Требования к проводке, из результатов пятого раунда аудита:

1. Каждый ген обязан быть возвращаемым из `Substrate._genome_from_contours()`
   тем объектом, который его **потребляет**.
2. Для гена, чей эффект — решение, а не настройка, обязателен **поведенческий**
   тест: чтение обратно не отличает потреблённое значение от сохранённого. Для
   `meta_far_share` — доля дальних кандидатов в выпуске; для `meta_mechanism_c` —
   изменение порядка; для `meta_min_effect` и `meta_ablation_n` — изменение числа
   подтверждённых правок на подготовленном наборе.
3. Ген, который не удаётся сдвинуть на 0.01 фитнеса, удаляется из генома, а не
   остаётся крутиться.

### M11.7.5. Конфиг

`META_ENABLED` (по умолчанию `False`, как `EVO_ENABLED` — поколение аблаций не
должно стартовать из-за длинного теста), `META_MAX_EDITS`, `META_ABLATION_N`,
`META_MIN_EFFECT`, `META_FDR_Q`, `META_FAR`, `META_NEAR`, `META_FAR_SHARE`,
`META_MECHANISM_C`, `META_RETIRE_AFTER`, `META_SCAN_EVERY_N_TICKS`,
`META_MAX_EXPLANATIONS`.

Ни одно имя не входит в `IMMUTABLE_PARAMS`; `META_ENABLED` входит в
`BOUNDED_PARAMS` как булев тумблер, недоступный политике поведения.

### M11.7.7. API (§M10.1) и дашборд

`GET /api/meta/explanations` · `/api/meta/explanation/{strategy}` ·
`/api/meta/mechanisms` · `/api/meta/skeletons` · `/api/meta/order/{weakness}`.
Все под тем же токеном и за `_kill_switch_guard()`.

Дашборд: панель на вкладке «Мышление» — таблица механизмов с долей побед,

`unsupported`), отставленные скелеты. Каждое читаемое поле обязано покрываться
контрактным тестом дашборда.

### M11.7.8. Персистентность (§3.2)

`data/metacognition/explanations.json`, `mechanisms.json`, `retired.json`.
`schema_version = 1` при введении, запись атомарная (tmp + `os.replace`), чтение
через `store/migrations.py::read_store` с регистрацией в `MIGRATIONS`. Файл из
будущей версии не читается. Объяснения ограничены `META_MAX_EXPLANATIONS`;
вытеснение — по возрасту, но `contested` и `supported` вытесняются последними:
`unsupported` — самый дешёвый для восстановления.

## M11.8. Детерминизм (§3.1)

Ни `random`, ни `numpy.random`, ни `secrets`. Порядки — детерминированный UCB с
каноническим тай-брейком; заполнение скелетов — по таблице кредита и
каноническому порядку; выборки для аблации — хеш-индексация `blake2b` от
`(стратегия, правка, позиция)`. Два прогона `meta_bench.py` из одного состояния
обязаны дать побайтово одинаковые реестр объяснений и таблицу кредита.

---

## M11.9. Безопасность (§3.3)

1. Синтезированная стратегия остаётся данными: 12 операций, интерпретатор умеет
   ровно их, каждый шаг считается в один бюджет, стратегия достаёт только то,
   что ей передали. M11 этого не расширяет.
2. Кортекс не влияет ни на одно число: `narrative` и предложенный механизм —
   наблюдения, вычисленная атрибуция — решение.
3. `attribute_strategy` и `invent_strategy` не `safety_critical` и подчиняются
   kill-switch, аренде ресурсов и этическому гейту.
4. Ни один ген M11 не приближается к порогам этики, kill-switch, песочнице и
   контрольной плоскости (тест над `IMMUTABLE_PARAMS`).

## M11.10. Критерии приёмки

Все — воспроизводимые прогоны, не утверждения.

1. **Атрибуция находит подсаженную причину.** На ≥20 подготовленных случаях, где
   выигрыш несёт ровно одна правка, аблация указывает именно её: точность 1.0,
   полнота 1.0.
2. **Ноль подтверждённых атрибуций на шуме.** Для стратегий, чей «выигрыш» —
   шум выборки, из ≥200 сравнений подтверждено **0**. Это гейт на BH-коррекцию.
3. **Кредит меняет порядок и ускоряет синтез.** `order_delta > 0`, и число
   кандидатов до принятой стратегии падает на **≥25%** против базовой линии с
   фиксированным порядком за 30 циклов (`scripts/meta_bench.py`).
4. **Дальний генератор не декоративен.** Медианное расстояние принятых дальних
   кандидатов `≥ META_FAR`, и **хотя бы одна** принятая за 30 циклов стратегия
   происходит от дальнего генератора. Без этого критерия ветка «принципиально
   другой способ» имела бы право никогда не срабатывать — тот самый класс
   дефекта, что был найден в пятом раунде аудита у декоративных генов.
5. **Нет регрессии.** Общий бенчмарк рассуждений не падает (`Δ ≥ −0.01`), доля
   уверенных ошибок не растёт.
6. **Объяснение без опоры не управляет ничем.** Тест: `unsupported` объяснение не
   меняет порядок синтеза.
7. **Кортекс не может переписать вывод.** Тест с провайдером, который называет
   механизм, противоречащий вычисленному: статус `contested`, порядок — по
   вычисленному.
8. **Бюджеты.** REFLECT ≤ 15 мс с включённой метакогницией, замер по реальным
   часам в подпроцессе. Аблация никогда не исполняется внутри `tick()`.
9. **Детерминизм.** Два прогона — идентичные реестры (M11.8).
10. **Интерпретатор не расширен.** `len(OPS) == 12`.
11. **Система работает без модуля.** При `META_ENABLED=False` контур рассуждений
    даёт те же результаты, что до M11 (регрессионный тест на неизменность).

## M11.12. Мутационные цели

В `scripts/mutation_test.py` добавляются все шесть модулей `metacognition/` со
своими тестами. Гейт прежний: выживший неэквивалентный мутант красит сборку;

показан красным до реализации.

## M11.14. Риски и их закрытие

| Риск | Закрытие |
|---|---|
| «Почему» окажется правдоподобным текстом | Механизм присваивается вычисленной аблацией; текст кортекса не читается кодом; расхождение даёт `contested` |
| Новизна выродится в шум | Приёмка не смягчается; квота ограничена сверху; отставка скелетов вечна |
| Аблация съест бюджет | Только в пуле оценки; `META_MAX_EDITS × META_ABLATION_N` ограничены; тест падает при синхронном исполнении |
| Каталог скелетов станет свалкой | Попарное `distance ≥ META_FAR` — тест; каждый скелет обязан хоть раз быть принятым за 60 циклов, иначе выносится в отчёт как неоправданный |
| Ген окажется декоративным | Read-back из потребителя + поведенческий тест на каждый ген; правило из пятого раунда аудита |
| Модуль станет обязательным | `META_ENABLED=False` по умолчанию; критерий 11 требует неизменности контура без него |

### Что потребуется, чтобы снять границу M11.2.4

Свободное порождение структуры вместо перебора по каталогу требует трёх вещей,
которых сейчас нет: (1) грамматики стратегий с доказуемой завершимостью любого
порождения, (2) верификатора, отклоняющего порождение с недостижимыми шагами до
исполнения, (3) бюджета на оценку, растущего не быстрее, чем логарифм от
размера пространства. Ни одна из трёх не является исследовательски открытой, но
каждая — отдельный объём работ, и вводить их под видом «заполнения каталога»
было бы нечестным занижением оценки.
