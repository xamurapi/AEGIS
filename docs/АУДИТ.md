## CRITICAL

**C1. Побег из песочницы skills через `__builtins__`** — `aegis/eval/sandbox.py:96-107`
AST-проверка `check_safe` применяет правило dunder-имён только к `ast.Attribute.attr`,
но не к `ast.Name.id`. Имя `__builtins__` не в `FORBIDDEN_CALLS`, а `.eval`/`.exec`
не являются dunder → `__builtins__.eval("__import__('os').system(...)")` проходит
фильтр и исполняется. Так как skills синтезируются автономно, это полноценный RCE
без участия человека. **Фикс:** блокировать любые `__*__` имена в ветке `ast.Name`,
либо запускать в реальном OS-sandbox/контейнере.

**C2. Цепочка indirect prompt injection → перезапись собственного кода** —
`substrate.py` (external_learning → semantic-память → LLM-промпт → code self-mod)
Непроверенный внешний контент (Wikipedia/arXiv/фиды) попадает в semantic-память,
оттуда в промпты, а тот же LLM-канал генерирует полные перезаписи файлов пакета
`aegis`, применяемые на диск и исполняемые после рестарта вне sandbox. Защита —
только чёрные списки паттернов и эвристики этики. **Фикс:** белый список изменяемых
зон, обязательное ревью человека или изолированный прогон применённого кода.

## HIGH

**H1. Data race на общей `SkillLibrary`/`Evaluator` между executor-потоками** —
`substrate.py:684-707, 725-880` + `eval/skill_library.py`
`environment.step` (executor, каждые 2 тика) итерирует `skill_library`, пока
`_skill_synthesis`/`_optimization` (event loop) делают `add()/remove()/save()`.
На тиках 200/400… `_eval_task` и `_skill_synth_task` стартуют одновременно.
Отказы: `RuntimeError: dictionary changed size during iteration`; порча `skills.json`;
искажённый замер `before/after`, из-за которого гейт принимает вредный skill или
ретайрит рабочий. **Фикс:** единый `asyncio.Lock`/`threading.Lock` вокруг доступа к
библиотеке.

**H2. Блокирующая загрузка модели в корутине** — `weight_modifier.py:224-231`
`load_model()` вызывается прямо в `async def train`, а не через `run_in_executor`.
Загрузка/квантизация LLM (гигабайты) замораживает весь tick-цикл на минуты.
**Фикс:** вынести `load_model` в executor.

**H3. Нет таймаутов на сетевые вызовы LLM** — `llm.py:246-251, 278-284`
`chat.completions.create` / `messages.create` без `timeout=` и `asyncio.wait_for`.
Зависший провайдер вешает `/api/chat` и фоновые задачи на дефолт SDK (до 10 мин).
**Фикс:** явный `timeout` + `asyncio.wait_for`.

**H4. CSWSH / нет проверки Origin на WebSocket** — `api/server.py:705-727`
WS не подчиняется CORS и не проверяет `Origin`. При дефолте (пустой токен, loopback)
любая веб-страница подключается к `ws://127.0.0.1:8888/ws`, читает `full_status()` и
активирует kill-switch. **Фикс:** проверка `Origin`, требование токена на WS.

## Дополнительно найдено при написании тестов (2-я волна)

Эти дефекты всплыли, когда покрытие остальных модулей доводилось до ≥85%:

- **A1 (security). `open(..., 'w')` не блокируется валидатором** — `code_modifier.py`.
  `validate_safety` ловит только две hardcoded-подстроки (`open('/etc`, `open('C:\Windows`),
  а `open` отсутствует в `DANGEROUS_CALL_NAMES`. Код `open('any.txt','w').write(...)`
  проходит и AST-, и подстрочную проверку → запись в произвольный файл мимо
  safety-слоя. Усугубляет C1/C2.
- **A2. Многословный `backup_type` обрезается** — `state_backup.py` (`_rotate_backups`,
  `list_backups`). Тип берётся как `filename.split("_")[1]`, поэтому `"pre_shutdown"`
  усекается до `"pre"` — разные типы ротируются вместе и мислейблятся. Латентно
  (сейчас только `scheduled`/`emergency`), но реальный баг при compound-типах.
- **A3. Неатомарная запись стат-файлов (подтверждено)** — `llm.py:161`,
  `weight_modifier.py:64` пишут `write_text` напрямую; краш в момент записи → битый
  JSON → загрузка молча сбрасывает всю накопленную статистику в ноль. (См. L7.)
- **A4. Бюджет LLM тратится на упавшие вызовы** — `llm.py:314-315` инкрементит
  счётчик и таймер ДО вызова провайдера; неудачный вызов всё равно съедает бюджет.
- **A5. `rollback_to_checkpoint` пишет состояние до проверки загрузки** —
  `weight_modifier.py:429-431`: `_save_stats()` до `load_model()`; при провале
  загрузки на диске остаётся указатель на неработающий чекпоинт.

Мёртвый/защитный код (не баги, задокументировано): недостижимая ветка
`recovery→normal` в `meta_regulation.py:46-47`; дефолтные fallback'и в `dreams.py:69`,
`emotion_nlp.py:48`; дважды присваиваемый `ethics_approved` в `self_modification.py:262-263`.

## Как подключается новый слой к Substrate (для интеграции)

1. Атрибут в `Substrate.__init__`.
2. Вызовы в нужной фазе `tick()` с периодом `tick_count % N` (константы в `config.py`).
3. Строка `"<name>": module.status()` в `full_status()`.
4. Persistence: `save()` в `_save_checkpoint()`; тяжёлые операции — по образцу
   `_run_benchmark` (detached task + executor), с учётом H1 (общие структуры между
   потоками сейчас без локов).
