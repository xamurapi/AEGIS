# Пять ключевых систем AEGIS

Реализация пяти систем из спецификации (`создать.txt`), поднимающих AEGIS со
«слоя, управляющего собой» до «слоя над GPT», который понимает мир, связывает
опыт, эволюционирует по реальной метрике, действует из мотивации и учится на
результатах.

Все системы **детерминированы** (без `random` в ядре), персистентны (атомарная
запись JSON/JSONL), с ограниченным ростом структур, и подключены к
`Substrate.tick()`. LLM используется опционально, только для обогащения.

## 1. World Model — `aegis/layers/world_model.py`
Причинно-следственная модель мира (проблема №1 спецификации).
Учит связи `причина → следствие` из **реальных** исходов (шаги среды, решения) и
строит цепочку для цели:

```
цель → ограничения → риски → план → ожидаемый результат
```

- `observe(cause, effect, success)` — запись наблюдения; сила связи = сглаживание
  Лапласа `(успехи+1)/(наблюдения+2)`.
- `predict / explain / risks_for` — прогноз следствий, поиск причин, слабые (часто
  проваливающиеся) связи.
- `build_chain(objective)` — детерминированная цепочка; `refine_chain(parsed)` —
  приём уточнённой LLM-цепочки.
- Подключение: наблюдения из env-шага и исхода решения в `_act`/`_reflect`; цепочка
  для текущего фокуса в `_decide`.

## 2. Cognitive Graph — `aegis/layers/cognitive_graph.py`
Типизированный граф знаний и опыта (проблема №5).
Узлы: `concept | event | skill | goal | outcome`; рёбра: `relates_to | causes |
requires | learned_from | led_to`.

- `add_node / add_edge` (усиление веса при повторе), `ingest_memory(memory)` —
  инкрементальное наполнение из памяти со связыванием событий и концептов по общим
  токенам.
- `find_path` (BFS), `related` (Jaccard + бонус за степень), `central_nodes`.
- Подключение: `ingest_memory` в `_reflect` по расписанию.

## 3. Evolution Engine — `aegis/layers/evolution_engine.py`
Эволюция версий (проблема №2: self-modification ≠ саморазвитие).

```
чемпион (версия A) → мутация → кандидат (версия B) →
held-out бенчмарк = фитнес → оставить только если ЛУЧШЕ, иначе откат
```

- `register_champion / propose_mutation / judge_candidate / abandon_candidate`.
- Ключевой принцип: судья — **реальный held-out бенчмарк**, а не синтетическая
  песочница. Мутация применяется после проверок self-preservation + этики и
  клампинга по границам; отклонённая — откатывается к старому значению.
- Подключение: `_evolution_step` в `_act`, суд в `_run_benchmark`.

## 4. Goal Intelligence — `aegis/layers/goal_intelligence.py`
Мотивация, а не только «внутренние состояния» (проблема №4).

```
цель → ценность → выбор действия → награда
```

- Внутренние драйвы (`competence/knowledge/coherence/stability`), модулируемые
  контекстом (низкая энергия → стабильность, высокая ошибка → когерентность).
- `choose(objectives, context)` — выбор по ожидаемой ценности; `reward(realized)` —
  TD-обновление полезности от реальной награды.
- Подключение: выбор в `_decide`, награда от `_compute_reward()` в `_reflect`.

## 5. Real-world Feedback Loop — `aegis/layers/feedback_loop.py`
Обучение из опыта (проблема №5).

```
ситуация → решение AEGIS → реальный результат → оценка → причина → новый опыт
```

- `record_situation` открывает опыт, `record_result` закрывает его реальным исходом
  и **причиной** успеха/провала (структурированная строка, не сырой текст).
- `export_examples()` — датасет для LoRA: `prompt`(ситуация+решение) →
  `completion`(результат+причина). Именно это отвечает на вопрос спецификации «что
  попадает в датасет».
- Подключение: открытие в `_decide`, закрытие с наградой в `_reflect`.

## Интеграция в Substrate

Все пять доступны как атрибуты `substrate.world_model`, `.cognitive_graph`,
`.evolution`, `.goal_intelligence`, `.feedback_loop`, сохраняются в
`_save_checkpoint()` и публикуются в `full_status()` (видны на дашборде и через
`/api/status`). Все вызовы в tick обёрнуты в `try/except` — сбой любой системы не
может уронить когнитивный цикл.
