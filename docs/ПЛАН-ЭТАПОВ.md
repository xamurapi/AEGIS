## Этап 5 — Политика поведения (M3) ✅ сдан

Замыкает пятое звено `действие → результат → оценка → знание → **изменение
поведения**`. До него опыт менял только штраф уверенности; после — существует
отдельный наблюдаемый объект, который меняет ранжирование планов.

**Файлы.** `aegis/layers/policy/store.py` (предпочтения `(s,a) → вес`),
`rules.py` (`Rule`, `RuleMiner`, `RuleLifecycle`), `counterfactual.py`
(`ShadowEvaluator`), `scripts/ab_policy.py`.

**Ключевые решения.**
- Обучение преимуществу, не абсолютной награде: `w ← w + η·(r − baseline(s))·(1 − |w|)`.
  Базис — скользящее среднее награды в этом состоянии, иначе политика выучит
  «в хороших состояниях всё хорошо».
- Правило активируется только после теневой проверки: интерливинг ABAB по
  чётности тика, Welch t, `p < 0.05`, `effect > POLICY_MIN_EFFECT`.
- Контроль ложных открытий — Бенджамини–Хохберг по всему поколению кандидатов.
- `safety_critical`-действия неподавляемы (Приложение A).
- Опровергнутые правила хранятся вечно — антидребезг против переоткрытия.

**Признак завершения.** Сценарий подавления (30 провалов `A` в состоянии `S` →
активное правило `suppress(S,A)`, `A` перестаёт быть топ-выбором в `S` и
остаётся доступным в других состояниях); обратный сценарий (мир изменился →
правило уходит в `retired`); ноль активных правил на чистом шуме;
`behaviour_delta_rate > 0` на 2000 тиков; `scripts/ab_policy.py` показывает
награду с политикой не ниже, чем без неё.

## Этап 6 — Пул оценки, сплиты, генераторы (M9.1, M9.3) ✅ сдан

Инфраструктура, без которой этапы 7 и 9 нечем мерить.

**Файлы.** `aegis/eval/pool.py` (`EvaluationPool`), правки
`benchmark.py`/`evaluator.py`/`solver.py`/`skill_library.py`,
`tests/test_no_leakage.py`.

**Ключевые решения.**
- Тройной сплит `train/valid/test` фиксируется хешем id задачи, а не позицией —
  добавление задачи не должно переселять существующие.
- Генераторы вариаций для существующих видов задач: библиотека навыков не должна
  уметь «выучить константы».
- `SkillLibrary.snapshot()` — изолированная оценка варианта не трогает живую
  библиотеку.
- Пул: детерминированный порядок результатов по индексу, жёсткий таймаут на
  задачу, учёт `subprocess_slots` в `ResourceManager`.

**Признак завершения.** Тест изоляции (оценка не меняет живую библиотеку);
тест утечки (ни один текст held-out задачи не попадает в промпт синтезатора).

## Этап 7 — Популяционная эволюция (M5) ✅ сдан (критерий +15% — см. docs/QA.md §B2)

**Файлы.** `aegis/layers/evolution/{genome,operators,population,harness}.py`,
`evolution_engine.py` как фасад v2, `scripts/evo_bench.py`.

**Ключевые решения.**
- Новый геном (Приложение C) состоит только из параметров, которые доказуемо
  меняют измеряемое поведение; старые LoRA-параметры выходят из генома и
  остаются в `SelfModification.parameters`.
- Поколение: 2 элиты + 4 координатные мутации + 2 кроссовера + 1 крупный шаг +
  1 от кортекса = 10.
- Отбор только по `valid`; `test` — единственное подтверждение чемпиона.
- Откат чемпиона при деградации живой метрики.

**Признак завершения.** +15% фитнеса за 20 поколений; `valid_test_gap ≤ 0.05`;
тест чувствительности каждого гена; невозможность включить `IMMUTABLE_PARAMS`
в геном ни через кортекс, ни через миграцию.

## Этап 8 — Бенчмарк рассуждений, DSL, интерпретатор (M6.3–M6.5)

**Файлы.** `aegis/layers/reasoning/{dsl,interpreter,library}.py`,
`aegis/eval/reasoning_bench.py`, восемь встроенных стратегий (Приложение E).

**Ключевые решения.**
- DSL — не Python: собственный интерпретатор с фиксированным набором операций,
  жёстким лимитом шагов и стоимостью каждой операции в `ResourceCost`.
- Бенчмарк — генераторы `build(i) -> ReasoningTask`, а не список: неограниченный
  held-out без RNG и без утечки.
- Каждая задача несёт программный верификатор и метки признаков — они же оси
  детектора слабостей.

**Признак завершения.** Лимиты интерпретатора (включая вечный `LOOP`);
детерминизм трасс; генераторы без коллизий.

## Этап 9 — Слабости, синтез, арена (M6.6–M6.9)

**Файлы.** `aegis/layers/reasoning/{weakness,synthesis,arena}.py`,
`scripts/reason_bench.py`.

**Ключевые решения.**
- Шаблонный путь синтеза работает без LLM — шесть чистых трансформаций DSL.
- Приёмка требует одновременно прироста на held-out, отсутствия регрессии на
  общем наборе и стоимости не выше `REASON_COST_TOLERANCE`.
- Выбор стратегии в проде — детерминированный UCB, без ГСЧ.

**Признак завершения.** +15 п.п. held-out за 30 циклов; отсутствие регрессии
общего бенчмарка; падение доли «уверенных ошибок».

## Этап 10 — Discovery Engine (M7)

**Файлы.** `aegis/layers/discovery/{datapool,hypothesis,symbolic,experiment,statistics,ledger}.py`.

**Ключевые решения.**
- Главный источник данных — собственная телеметрия (M9.2).
- Символьная регрессия — детерминированный луч по возрастанию сложности, отбор
  по BIC/MDL; результат обязан быть формулой.
- Предрегистрация с замороженным хешем плана: отклонение плана = `invalid`.
- Интервенционный ABAB только по белому списку, с откатом по таймеру и
  немедленным откатом при `health != ok`.

**Признак завершения.** Восстановление подсаженной формулы `R²_valid ≥ 0.9`;
ноль `supported` открытий на 1000 проверок шума; откат интервенции при
`health=critical`.

## Порядок и почему именно такой

`5 → 6 → 7` и `6 → 8 → 9 → 10`: политике поведения нужен планировщик, чтобы
было на что влиять; эволюции и арене нужен изолированный пул и честные сплиты,
иначе «улучшение» будет переобучением; Discovery Engine нужна телеметрия за
длительное время и статистика, отлаженная на более простых контурах.
