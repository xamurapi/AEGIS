# Улучшение алгоритмов мышления (M6)

`найти слабость мышления → создать новые алгоритмы рассуждения → проверить →
оставить улучшение`

Мышление становится **данными**: стратегия рассуждения — объект с версией,
стоимостью, применимостью и измеренной эффективностью.

---

## 1. Почему стратегия — не Python

Это вся позиция безопасности контура. Стратегии синтезируются, один из
синтезаторов — языковая модель, и синтезированная стратегия, будь она Python,
означала бы исполнение произвольного кода под дружелюбным именем.

Здесь стратегия — список записей из двенадцати операций, исполняемый
интерпретатором, который умеет ровно эти двенадцать и ничего больше, считает
каждый шаг против одного бюджета и дотягивается только до того, что ему
передали.

| Операция | Смысл |
|---|---|
| `DECOMPOSE` | разбить задачу на подзадачи |
| `RETRIEVE` | подтянуть контекст из памяти, графа или библиотеки навыков |
| `PREDICT` | спросить модель мира об исходе варианта |
| `SOLVE` | вызвать навык через песочницу |
| `COMPUTE` | детерминированное вычисление |
| `LLM_STEP` | шаг кортекса со схемой ответа |
| `VERIFY` | проверить промежуточный результат |
| `VOTE` | n независимых прогонов ветви и агрегация |
| `BRANCH` | ветвление по предикату |
| `LOOP` | ограниченный цикл с жёстким лимитом |
| `REFLECT` | записать вывод в трассу и переоценить |
| `ABSTAIN` | отказ от ответа |

`validate()` возвращает **все** проблемы, а не первую: синтезатор, которому
выдают по одной ошибке за раз, исправляет по одной ошибке за раз.

---

## 2. Лимиты, с которыми нельзя спорить

- Бюджет шагов считается **сквозь вложенность**: `LOOP` с телом из восьми
  шагов и восемью итерациями не стоит восемь.
- Потолок итераций `LOOP` не зависит от того, что просит стратегия. `LOOP` с
  всегда-истинным условием завершается — это именованный негативный тест M6.10.
- Ген может тратить в пределах лимита, но не сверх него.
- Бюджет ноль всё равно даёт один шаг: стратегия, не сделавшая ни шага,
  неотличима от отсутствия стратегии и прячет неисправность.
- Верификатор бенчмарка стратегии **недоступен**: ни один checker не может
  сообщить правильный ответ.

Трасса детерминирована: два прогона одной стратегии на одной задаче дают
структурно одинаковую запись (без стенных часов). Без этого ничто в контуре не
сравнимо между прогонами и любой измеренный прирост неопровержим.

---

## 3. Слабость — это не «мышление слабое»

`Weakness` — это **комбинация признаков задачи** (`family=arithmetic_chain` и
`incomplete`, скажем) вместе с частотой провала, объёмом доказательств и
превышением над собственной средней системы.

Три вещи не дают выдумывать слабости:

**Базовая частота.** Группа слаба только относительно того, что система делает
везде. Система, проваливающая треть всего, не имеет слабости на 33% — у неё
такой уровень.

**Контроль ложных открытий.** Каждый признак и каждая пара — гипотеза, и их
сотни; при α = 0.05 примерно каждая двадцатая бесполезная выглядела бы
настоящей. Бенджамини–Хохберг по всему семейству — это то, что делает слово
«значимо» осмысленным, когда проверки посчитаны.

**Отсечение специализаций.** Если `family=arithmetic_chain` проваливается и
`family=arithmetic_chain AND numeric` проваливается так же, второе — это первое
в более длинном имени. Сообщить оба значило бы послать синтезатор за одной
проблемой дважды и разделить доказательства пополам.

---

## 4. Синтез: два пути, и порядок важен

**Шаблонный путь** — шесть чистых функций над DSL: добавить проверку, разбить
задачу, спросить больше раз, вычислить вместо запроса, посмотреть перед
прыжком, знать, когда не отвечать. Модель не нужна, путь работает всегда, и
именно он делает контур рабочим в развёртывании вообще без кортекса.

**Путь кортекса** — модели показывают слабость, провальные примеры, текущую
стратегию и грамматику; она возвращает новую стратегию строго по схеме.

Оба дают кандидатов, и ни одному не доверяют: библиотека отказывает всему, что
интерпретатор не смог бы исполнить, арена — всему, что не помогает, и лишь
после этого стратегия получает трафик. Кандидаты дедуплицируются по
нормализованному хешу DSL.

---

## 5. Арена: три гейта одновременно

- **Помогает**: `Δpass` на held-out половине слабого класса ≥ `REASON_MIN_GAIN`.
  Измеряется на задачах, которые не использовались ни для поиска слабости, ни
  для отладки кандидата, — иначе прирост есть подгонка под показанные примеры.
- **Ничего не ломает**: `Δpass` на общем наборе не хуже −0.01. Стратегия,
  выигрывающая свой класс ценой проигрыша везде, — это стратегия, которой
  быть не должно, и без этого гейта система накапливала бы их по одной на
  слабость.
- **По карману**: стоимость в пределах `REASON_COST_TOLERANCE` от действующей.
  Обернуть всё в пятикратное голосование почти всегда покупает пункт точности;
  ценовой гейт — это то, что не даёт этому быть бесплатной победой.

Наборы задач берутся из непересекающихся диапазонов индексов (`1 000 000`,
`2 000 000`, `3 000 000`), а рабочая очередь идёт с нуля — кандидата никогда не
судят на том, на чём его настраивали.

Прохождение всех трёх не делает стратегию действующей — оно делает её
**испытуемой**: она получает каждый k-й запрос своего класса, и через
`REASON_TRIAL_N` применений её накопленная запись сравнивается с действующей по
**нижней границе** интервала. Асимметрия намеренна: вытеснить проверенную
стратегию должно быть труднее, чем с ней сравняться.

---

## 6. Выбор в проде

Три слоя, по порядку: доля трафика испытуемой стратегии (детерминированная, по
хешу запроса, а не по счётчику), минимальное число попыток каждой активной
стратегии на семействе, затем UCB по накопленным счётчикам. Без минимума одна
удачная первая попытка забирала бы семейство навсегда, потому что там больше
ничего никогда не запускалось бы.

---

## 7. Приёмка

`scripts/reason_bench.py`, 30 циклов, 200 held-out задач:

| Метрика | Старт | Итог | Порог |
|---|---|---|---|
| Доля решённых на held-out | 0.6850 | **0.9650** | +15 п.п. → факт **+28.0** |
| Доля уверенных ошибок | 0.3050 | **0.0000** | не должна расти |

Ни одна встроенная стратегия не решает бенчмарк в одиночку — это сделано
намеренно: библиотека, уже содержащая лучшую стратегию, сделала бы M6
непроверяемым, потому что каждый измеренный прирост был бы селектором,
переоткрывающим написанное человеком.

Мутационный балл контура — 100% (`weakness` 25/25, `synthesis` 22/22,
`arena` 23/23).

## 8. Метрики и переменные

```
aegis.reason.pass_holdout       доля решённых на held-out
aegis.reason.strategies_active  активных стратегий
aegis.reason.win_rate{strategy} нижняя граница доли побед, по стратегиям
aegis.reason.abstain_rate       доля отказов
aegis.reason.confident_error    доля уверенных ошибок

REASON_MAX_STEPS=24        потолок шагов интерпретатора
REASON_MIN_GAIN=0.05       прирост, требуемый от кандидата
REASON_COST_TOLERANCE=1.5  во сколько раз кандидат может быть дороже
REASON_TRIAL_N=50          применений до суждения об испытуемой
REASON_SCAN_EVERY_N_TICKS=300
REASON_UCB_C=1.4           константа исследования при выборе
```

`aegis.reason.confident_error` — самая важная из них: система, которая ошибается
будучи уверенной, хуже, чем система, которая молчит.
