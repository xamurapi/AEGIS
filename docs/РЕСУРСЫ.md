# Мотивация с ресурсами (M4)

`цель → ценность → приоритет → ресурс → действие`

Цель и ценность существовали и раньше. Не существовало двух последних звеньев,
и без них мотивация — это мнение: всё хочется одинаково, и ни за что не платят.

---

## 1. Ресурс — то, что кончается

`ResourceManager` учитывает семь видов: `llm_tokens`, `llm_calls`, `wall_ms`,
`subprocess_slots`, `training_slots`, `disk_bytes`, `net_calls`.

Действие без выданной аренды **не выполняется** — оно откладывается. Это и
делает мотивацию настоящей: пока ресурс не выделен, желание остаётся желанием.

**Отказ — нормальный исход, а не ошибка.** Тик продолжается, действие
переносится, счётчик `aegis.res.denied` растёт. Система, падающая при нехватке
токенов, была бы системой, которая не умеет быть бедной.

**Коммитится фактический расход, а не оценка.** Резерв — это прогноз; разница
возвращается в бюджет. Иначе действие, зарезервировавшее щедро и потратившее
мало, навсегда сокращало бы собственное довольствие.

**Вытеснения нет.** Уже выданная аренда неприкосновенна: действие, начавшее
работу, нельзя «не начать». Конфликт разрешается порядком обращения и
старением.

**Пол безопасности.** Доля бюджета, которую нельзя отнять у чекпоинтов,
проверок здоровья и этики (`RESOURCE_SAFETY_FLOOR`). Проверка здоровья, которую
может уморить голодом обычная работа, — это не проверка здоровья, а пожелание.

## 2. Приоритет — явное число

```
priority = value·w_v + urgency·w_u + drive_pressure·w_d
         + aging·w_a + plan_ev·w_p − cost_norm·w_c
```

Все веса — часть генома (Приложение C), а не константы: если приоритезация
влияет на результат, её настройки обязаны быть предметом отбора.

**Старение ограничено сверху.** Ожидание поднимает приоритет, иначе
низкоприоритетная работа не выполняется никогда. Но неограниченное старение
превращает антиголодание в другое голодание — в котором ничего ценного не
выполняется, потому что всё вытеснено давно ждущей мелочью. Потолок —
`min(1.0, waited · PRIORITY_AGING)`.

## 3. ROI — куда уходит бюджет

`ROITracker` ведёт по каждому виду активности потраченные ресурсы и полученную
величину, сглаженные по Уэлфорду. Раз в `RESOURCE_REALLOC_EVERY_N_TICKS` доли
перераспределяются пропорционально ROI.

Два ограничения, каждое закрывает свой способ сломаться:

- **Отрицательный ROI зажимается в ноль, а не инвертирует пропорцию.**
  Активность, которая сейчас в убытке, должна финансироваться меньше, а не
  наоборот.
- **Ни одна активность не получает нуля** (`RESOURCE_MIN_SHARE`). Активность с
  нулевым бюджетом никогда не обновит собственный ROI, поэтому ноль — это дверь
  в одну сторону.

Бесплатная активность, давшая результат, не бесконечно прибыльна — она просто
дёшева; её стоимость зажимается снизу наименьшей единицей, которую взвешивание
способно выразить, иначе одно бесплатное действие забрало бы весь бюджет.

---

## 4. Единственный путь к кортексу

`Cortex.call` требует валидный `Lease`. Это заменяет прежнюю надежду на то, что
`LLM_MAX_CALLS_PER_RUN` выставлен достаточно щедро; сам предохранитель остаётся
как верхняя граница.

## 5. Приёмка

| Критерий (M4.7) | Как проверяется |
|---|---|
| При нулевом токенном бюджете система тикает, ни одна фаза не падает | `test_resources.py`, BDD `features/motivation.feature` |
| Низкоприоритетная активность получает ресурс не позже `PRIORITY_AGING_MAX_TICKS` | `test_priority.py` |
| Полы безопасности держатся при попытке перераспределить всё в обучение | `test_resources.py` |
| При нулевой отдаче доля падает до `RESOURCE_MIN_SHARE`, но не до нуля | `test_roi.py` |
| Сквозной: цель→ценность→приоритет→аренда→действие→награда→ROI | `test_motivation_chain.py` |

## 6. Метрики

```
aegis.res.spent{kind}      израсходовано по видам
aegis.res.denied           отказов в аренде
aegis.res.starvation_ticks тиков ожидания
aegis.res.roi{activity}    отдача по активностям
aegis.res.share{drive}     текущее деление бюджета
```

## 7. Переменные окружения

```
RES_TOKENS_PER_HOUR=200000   RES_CALLS_PER_HOUR=400
RES_WALL_MS_PER_TICK=2500    RES_SUBPROC_SLOTS=4
RES_TRAINING_SLOTS=1         RES_DISK_MB=4096
RESOURCE_SAFETY_FLOOR=0.15   доля, недоступная обычной работе
RESOURCE_MIN_SHARE=0.05      пол под долей любой активности
RESOURCE_REALLOC_EVERY_N_TICKS=500
PRIORITY_AGING=0.01          прирост приоритета за тик ожидания
PRIORITY_AGING_MAX_TICKS=2000
```
